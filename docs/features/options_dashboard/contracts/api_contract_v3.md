# Options Live V3 API Contract

## 1. Scope
This contract defines stable V3 endpoints for new UI entry points, independent from existing options-live pages.

## 2. Entry Point Strategy
1. Build V3 under separate API namespace: `/api/options-live/v3/*`.
2. Do not modify existing V1/V2 payload shapes.
3. Keep backward compatibility with Pine outputs generated by existing scripts.

## 3. Response Envelope
All endpoints return:
1. `success: boolean`
2. `data: object | array | null`
3. `meta: object`
4. `warnings: string[]`
5. `error: string | null`

Meta fields:
1. `symbol`
2. `asOf`
3. `freshnessMs`
4. `source`
5. `computeVersion`
6. `adapterVersion`

## 4. Read Endpoints
### 4.1 Summary
- Method: GET
- Path: `/api/options-live/v3/summary`
- Query:
1. `symbol` (required)

### 4.2 By Strike
- Method: GET
- Path: `/api/options-live/v3/by-strike`
- Query:
1. `symbol` (required)
2. `strikes` (optional, default 20)
3. `expiryScope` (optional, default all)
4. `metricFamily` (optional: gamma, delta, charm, vanna)

### 4.3 By Expiry
- Method: GET
- Path: `/api/options-live/v3/by-expiry`
- Query:
1. `symbol` (required)
2. `strikes` (optional)
3. `metricFamily` (optional)

### 4.4 Largest By Strike and Expiry
- Method: GET
- Path: `/api/options-live/v3/largest`
- Query:
1. `symbol` (required)
2. `limit` (optional, default 25)
3. `sort` (optional, default abs_net)

### 4.5 Levels
- Method: GET
- Path: `/api/options-live/v3/levels`
- Query:
1. `symbol` (required)

### 4.6 Spot Gamma
- Method: GET
- Path: `/api/options-live/v3/spot-gamma`
- Query:
1. `symbol` (required)
2. `smooth` (optional, 1|3|5)

### 4.7 Heatmap
- Method: GET
- Path: `/api/options-live/v3/heatmap`
- Query:
1. `market` (required: spx|ndx)
2. `mode` (required: pcr|regular)
3. `metric` (optional: net_gex|abs_gex|volume|open_interest)
4. `strikes` (optional)
5. `expiryMode` (optional: exact|bucketed)

### 4.8 Narrative
- Method: GET
- Path: `/api/options-live/v3/narrative`
- Query:
1. `symbol` (required)

### 4.9 Recent Flow
- Method: GET
- Path: `/api/options-live/v3/recent-flow`
- Query:
1. `symbol` (required)
2. `limit` (optional, default 50)

### 4.10 Explain Snapshot
- Method: GET
- Path: `/api/options-live/v3/explain`
- Query:
1. `snapshotId` (required)

## 5. Publish Endpoints
### 5.1 Preview
- Method: POST
- Path: `/api/options-live/v3/publish/preview`
- Body: publish request payload

### 5.2 Discord Publish
- Method: POST
- Path: `/api/options-live/v3/publish/discord`
- Body: publish request payload

### 5.3 Event Rule
- Method: POST
- Path: `/api/options-live/v3/publish/event-rule`
- Body: event trigger config

## 6. Compatibility Rules
1. Existing outputs for `data/daily_levels.json` and `data/daily_levels.txt` must remain stable.
2. V3 fields must be additive for compatibility-sensitive payloads.
3. Breaking changes require version bump and migration note.

## 7. Performance and Reliability Requirements
1. p95 latency target for summary and levels endpoints <= 300ms under warm cache.
2. p95 latency target for heavy aggregations <= 700ms.
3. Every response includes freshness metadata.
4. All publish endpoints require idempotency key support.

## 8. Error Codes
1. `400` invalid query/body
2. `404` symbol or snapshot not found
3. `409` idempotency conflict
4. `429` rate limited
5. `500` internal error

## 9. Rollout
1. New UI entry points consume only V3 endpoints.
2. Existing UI remains untouched during V3 implementation.
3. Cutover occurs after M6 gates pass.
